  - **Post-review fix, commit `14ecc63`:** the original `budget_check_stage` was read-then-check (`GET` spend, compare to limit, allow), which races — concurrent requests can all read "under budget" before any of them records its cost, overshooting the limit by however many requests were in flight. Rebuilt spend accounting as reserve-then-reconcile, matching the atomicity the rate limiter already had: `reserve_and_check` (new, in `budget.py`) atomically adds a pre-call cost *estimate* (from `token_counter.estimate_input_tokens` + `max_tokens`/a default) to the Redis counter and checks it against the limit in one Lua script, so the check-and-write can't be raced. `usage_recording_stage` now calls `reconcile_reservation` post-call to correct the counter from the estimate to the real cost. Any early exit after a successful reservation — a later pre-call stage blocking, unknown model, upstream provider error, or a pipeline `StageFailure` — refunds the reservation via a new `_release_budget_reservation` helper in `app/api/chat.py`, or the counter would permanently overstate spend for a request that was never actually fulfilled.
  - Also fixed: an unpriced model used to make `usage_recording_stage` raise `UnknownPricingError` *after* the provider had already answered successfully, which fail-closed turned into a 503 thrown away on top of a good response. Now it logs a warning, records the `UsageRecord` with cost $0, and still returns the answer to the caller. The pre-call reservation estimate has the same fallback (reserve $0 rather than blocking on missing pricing data).
